# «Тунель» — бортова версія (Docker, вебінтерфейс)

Робоча тека нового напрямку. Тут збираються план, заміри й усе, що стосується бортової версії;
сам код «двигуна» з часом стане окремим пакетом у `apps/` цього ж репозиторію.

## Навіщо
- Програма працює **на борту**, оператор заходить **з будь-якого ПК через браузер** по VPN (LTE / Starlink).
  На наземний ПК нічого не встановлюється.
- **Усі налаштування зберігаються на борту**: помилка на наземному комп'ютері борт не зламає.
- Вхід за паролем: **пілот** бачить спрощений екран без налаштувань, **адміністратор** — усе.
  Обмеження перевіряється на борту, а не в браузері.
- Орієнтир за зручністю — BUDDY (вебінтерфейс на бортовому комп'ютері з відео й повним функціоналом).

## Залізо
| | Teltonika RUTC41 | Raspberry Pi 5 |
|---|---|---|
| Процесор | 2 × Cortex-A53, 1,3 ГГц | 4 × Cortex-A76 |
| Пам'ять | 1 ГБ, спільно з RutOS | 4–8 ГБ |
| Накопичувач | 8 ГБ eMMC | microSD / NVMe |
| Запуск | Docker | Docker або .deb |

Один образ `arm64` для обох. Вузьке місце — RUTC41: нинішня програма на Electron разом із Chromium
туди не вміститься.

## Задум
- **Без Electron і Chromium на борту.** На борту лише «двигун» на Node.js; інтерфейс малює браузер
  оператора. Розрахункова пам'ять 150–250 МБ — **це оцінка, її треба виміряти на RUTC41**.
- **Відео без перекодування:** mediamtx перепаковує RTSP у WebRTC. Камера має віддавати H.264.
- **Зв'язок інтерфейсу з двигуном — WebSocket** замість внутрішніх каналів Electron
  (на 1 жовтня 2026: близько 630 каналів у `apps/desktop/src/main/preload.ts`, близько 60 файлів
  ядра імпортують `electron` — числа перерахувати перед початком).
- **Не переноситься:** симулятор, 3D, прошивальник, окремі вікна (стають вкладками браузера),
  діалоги файлів (стають завантаженням / вивантаженням у браузері).
- **Переноситься майже без змін:** режим оператора, список бортів, панель керування, RC-рушій,
  повідомлення борту — вони вже відділені від Electron у `src/shared` та `src/main/operator`.

## Порядок робіт
1. **Прототип моста:** двигун без Electron піднімає зв'язок MAVLink і віддає телеметрію в браузер
   по WebSocket. Замір пам'яті й процесора на RUTC41.
2. **Ролі:** вхід пілота й адміністратора, перевірка на борту; екран оператора в браузері.
3. **Відео:** mediamtx у контейнері, WebRTC у браузер.
4. **Пакування:** Docker-образ arm64, запуск на RUTC41 і Pi 5, оновлення.
5. **Випробування на справжньому борту.**

## Відкриті питання до замовника
1. Як польотний контролер підключено до RUTC41 — напряму по USB чи через Raspberry Pi?
2. Скільки операторів одночасно дивляться і скільки керують?
3. Чи потрібно паралельно лишити доступ для QGC або BUDDY (пересилання MAVLink)?
4. Ліцензія: прив'язувати бортову версію до заліза борту так само, як настільну до ПК
   (`apps/desktop/src/main/license`, генератор `apps/keygen`)?
5. Чи є доступ до RUTC41 або Pi 5 для замірів на прототипі?
