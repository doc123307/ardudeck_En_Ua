# ТЗ «Стохід»: заплановано на потім

## 1. Перемикач перевірки оновлень
- У Налаштуваннях: перемикач «Перевіряти оновлення» (увімк./вимк.), щоб на бортових і польових ПК перевірку можна було вимкнути.
- Якщо файл оновлення недоступний (випуск — чернетка, GitHub відповідає 404), вважати, що оновлень немає, і не показувати червону помилку `[MAIN] Cannot find latest.yml` у консолі.

## 2. Бортова версія з вебінтерфейсом
- «Стохід» на борту: Teltonika RUTC41 (Docker) або Raspberry Pi 5. Оператор заходить з будь-якого ПК через браузер по VPN (LTE/Starlink).
- Усі налаштування зберігаються на борту.
- Вхід за логіном і паролем:
  - **пілот:** спрощений інтерфейс для польоту, без налаштувань;
  - **адміністратор:** повний функціонал за окремим паролем. Обмеження перевіряється на борту.
- Легкий «двигун» без Chromium (Node.js, ~150-250 МБ пам'яті), один Docker-образ arm64 для RUTC41 і Pi 5.
- Відео: mediamtx, RTSP → WebRTC у браузер без перекодування (камера має давати H.264).
- Відкриті питання:
  - як польотний контролер підключено до RUTC41 (USB чи через Pi);
  - камера й RTSP;
  - скільки операторів одночасно;
  - чи потрібне паралельне підключення QGC/BUDDY.

## 3. Режим оператора (настільна програма)
Програма одразу відкривається в режимі оператора. Повний інтерфейс («режим розробника») — лише для адміністратора, техпідтримки, ремонту й тестів.

**Вхід адміністратора**
- У режимі оператора є розділ **«Про програму»**: версія, посилання на підтримку `@stohid_support_bot` (бот буде пізніше) і **прихована іконка**.
- Довге натискання на приховану іконку → поле пароля адміністратора → повний режим.
- Вихід з адмін-режиму вручну або через 15 хв бездіяльності; програма повертається в режим оператора.
- Пароль зберігається у вигляді хешу. Процедура скидання — через підтримку.

**Екран оператора** (за прикладом модернізованого QGC)
- **Верхня смуга стану борту:** режим, супутники (кількість і фіксація), АКБ (В і %), час роботи з моменту ввімкнення, швидкість за GPS, кут крену й кут нахилу (з підсвіткою біля меж перекидання), індикатор запису.
- **Камери:**
  - основна на весь екран;
  - інші в мініатюрах: перетягувати, масштабувати, ставити в сітку;
  - клік робить камеру основною;
  - перемикання вручну;
  - на кожному потоці приховані кнопки керування: день/ніч, ІЧ, біле світло, SD/HD, зум;
  - задня камера — дзеркально.
- **Запис відео на ноутбук:** одна камера або всі, тека задається адміністратором.
- **Розкривна карта** зліва внизу; справа внизу — компас, висота, швидкість, час.
- **Кнопки виходів борту** (світло, габарити, ІЧ…) з індикацією реального стану.
- **Велика кнопка «СТОП» (Hold)** + клавіша Пробіл; ARM утриманням.
- **Стан аварійних дій** і зворотний відлік при втраті зв'язку.
- **Передвиїзна перевірка:**
  - автоматичні пункти: зв'язок, GPS, АКБ, EKF, перевірки ArduPilot, відео з камер, місце на диску, аварійні дії;
  - ручні пункти від адміністратора;
  - тест світла.
- **Якість каналу:** пінг, втрати, бітрейт камер, сигнал LTE/Starlink.
- **Зони габаритів** (статичні лінії на відео, як у камер заднього ходу).
- **Пробіг, витрачені мА·год, залишок ходу, температури, обмеження швидкості** «повільно/нормально».
- **Сповіщення** простою українською + голос.
- **Журнал сесії** для звітів, нічна тема, карта на другий монітор.

**Розділ адміністратора «Простір пілота»:** розташування камер, поля верхньої смуги, кнопки виходів, ручні пункти перевірки, калібрування зон габаритів, тека запису, пароль адміністратора, контакт підтримки.

**Не робимо:** автоперемикання на задню камеру при русі назад, динамічні лінії траєкторії. Віртуальні джойстики — пізніше.

**Відкриті питання:** які кнопки дій має оператор (Hold, RTL, Manual, ARM), чи може він змінювати режим і запускати місію, автопідключення при запуску, запис автоматично при ARM чи кнопкою, які додаткові дані є на борту (температури, датчики відстані).

**Вже зроблено (буде у 0.1.2-0.5):** сітка камер, керування Hikvision, SD/HD, дзеркало/поворот, цифровий зум, кнопки виходів через реле польотного контролера (RELAY1 — ближнє світло, RELAY2 — габарити; набір налаштовується).

## 4. Запропоновано, ще не підтверджено
- Переклад решти таблиць даних (пресети, шаблони Lua, елементи OSD).
- Щотижнева автоматична перевірка нових змін в оригінальному ArduDeck.
- Передати переклад автору оригіналу (запит на злиття).
